Work

A design system for four travel products

I built a shared design system so four booking products could look like themselves while running on one set of components.

Company
Firebird Tours group
Period
2023–2026
My role
Product designer, led design system work
Team
1 junior designer, front-end developers, PMs

Context

The group runs several travel brands for a global audience: train tickets, tours and an internal tool for travel agents. Each product had grown its own UI. The same date picker existed in five versions, and developers rebuilt components for every brand.

Problem

Design and development were slowed down by inconsistency, not by a lack of ideas. Mockups took long to prepare, handoff needed many clarifications, and the same user pattern behaved differently from site to site.

What I did

  • Token structure. Set up colour, type and spacing tokens with themes per brand, so a component changes its look by switching a theme rather than being redrawn.
  • Component library. Built and documented 2,000+ components and variants in Figma, from inputs and calendars to full booking blocks.
  • Design–code link. Worked with front-end developers to match the Figma library to Storybook across different tech stacks.
  • Workspace and rules. Reorganised the Figma workspace and wrote usage guidelines, then reviewed the junior designer’s work against them.

Outcome

  • Preparing UI mockups took the design team roughly half the time it used to, by our own estimate.
  • The system shipped in four consumer products and the internal agent tool.
  • Fewer review rounds and handoff questions, because patterns were decided once.

Numbers are internal estimates; I no longer have access to the original dashboards.
